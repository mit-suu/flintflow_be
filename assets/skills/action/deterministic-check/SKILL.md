# Deterministic Check

Contract for `deterministic-check.ts` (T09). A pure function over the Spine key graph. **Never calls a model.** Only these red flags block `baselines[]`; LLM judgement (review-section) only raises yellow flags.

## When it runs

| Moment | Scope |
| --- | --- |
| Review action of every step | Rules whose section is fed by the step |
| S-8.4 Consistency Pass | All rules (deterministic half; the LLM half is `review-section`) |
| S-9.5 Baseline Sign-off | **All rules on the current `spine_version`**; store `checked_at_version`. If `spine_version` changed between check and sign-off → reject and re-check |
| After every change transaction | Rules touching the changed keys |

## Rules

- 11 red rules: `references/red-rules.md`
- 11 yellow rules (cardinality, use case relations, naming): `references/yellow-rules.md`

Every red flag **must** carry an executable `remediation_step`. A red rule without one is a defect: the user would be stuck at the final gate.

## Flag record

```text
flags[] { id, level: red|yellow, rule_id, section_id, target_id?, message,
          remediation_step, opened_at_version, resolved_at,
          waived_by_user, waive_reason, waived_at_version }
```

- **Identity key**: `(level, rule_id, section_id, target_id, resolved_at IS NULL)`. A recurring flag creates a **new row**; never upsert over a closed row.
- `section_id` is a logical key (`fixed:3.1.3`, `function:FN07`) — never a section number.
- `message` in the user's language, naming the element (`Actor "Reviewer" has no use case`).
- Condition no longer true → set `resolved_at` (the rule, not the user, resolves).

## Waivers

- Waivable: every red rule except **`dead_reference`, `array_empty`, `render_error`** — those are broken invariants or technical errors; waiving them signs a baseline on a broken Spine.
- `waive_reason` is typed by the user, ≥ 20 characters, never generated by a model.
- **Waiver expiry**: if the current `spine_version` ≠ `waived_at_version` and the condition still holds, the waiver lapses and the flag reopens.
- `baselines[].waived_count > 0` ⇒ version `v1.0-conditional`, and every export lists the waivers in §I.

## Baseline condition

```text
count(flags[level=red, resolved_at=null, waived_by_user=false]) == 0
```

No percentage threshold, ever — users would invent content to hit the score (Phases §6.5). Yellow flags never block.

## Derived sections

`fixed:I` and `fixed:5.5` never raise `section_empty`, never go `stale`, and are excluded from the readiness score. `fixed:5.5` must be re-run at S-9.1 when `spine_version` > the version at which S-8.1 ran.
