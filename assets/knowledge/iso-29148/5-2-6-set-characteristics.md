---
source: ISO/IEC/IEEE 29148:2018
section: 5.2.6 Characteristics of a set of requirements
topic: requirements
description: The quality characteristics a whole set of requirements (for example an SRS) should have
status: verified
---

Besides the quality of each requirement, ISO/IEC/IEEE 29148 asks that the requirements of one entity, taken together
as a set, have these characteristics:

- **Complete**: the set covers every need the entity has to satisfy, with nothing important missing.
- **Consistent**: requirements in the set do not contradict each other, do not duplicate each other, and use the same
  terms for the same things.
- **Feasible**: the whole set can be met together within cost, schedule and technical limits, not only each
  requirement on its own.
- **Comprehensible**: readers can understand what is expected of the entity and how it relates to the system it is
  part of.
- **Able to be validated**: it is practical to show that satisfying the set will meet the stakeholder needs within the
  stated constraints.

In an SRS this means checking the document as a whole: missing functions, conflicting rules between sections, and
terms used with different meanings are defects of the set even when each requirement looks fine alone.
