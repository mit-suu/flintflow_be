ISO/IEC/IEEE 29148 describes the content expected in a software requirements specification (SRS). It groups the
content roughly as follows:

- **Introduction**: purpose of the document, scope of the software, product overview (perspective, main functions,
  user characteristics, limitations) and definitions of terms and acronyms.
- **References**: the documents the SRS relies on.
- **Specific requirements**: external interfaces, functions, usability, performance, logical database requirements,
  design constraints, standards compliance and software system attributes such as reliability, availability,
  security and maintainability.
- **Verification**: how each requirement will be verified, often presented as a table that pairs requirements with
  verification methods.
- **Supporting information**: appendices such as assumptions and dependencies, and acronyms.

The standard notes that the outline can be organised in different ways (for example by mode, user class, feature or
stimulus) as long as the content is covered. Content that does not belong to any of these groups, such as a project
cost estimate, is not part of the SRS itself.
